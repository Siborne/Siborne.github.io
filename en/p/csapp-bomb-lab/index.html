A complete walkthrough of all six phases of the CMU CS:APP Bomb Lab, with line-by-line x86-64 assembly analysis covering calling conventions, loops and arrays, jump tables, recursive binary search, bitwise character mapping, and linked list reordering with descending-order verification.

简体中文 繁體中文 日本語

Assembly is brutal — but getting through it opens up a whole new world.

The Bomb Lab is one of the most iconic experiments in CMU’s 15-213 (CS:APP) course. You’re given a binary executable called bomb with six phases. Each phase requires a specific password — enter the wrong one and the bomb explodes (the program prints “BOOM!” and deducts points). Armed with nothing but the executable and GDB, your mission is to disassemble, reverse-engineer, and deduce the password for each phase.

This article walks through all six phases in detail, from line-by-line assembly analysis to GDB techniques, and finally translating the assembly logic back to C.

Preparation

Before defusing, set up your GDB environment and safety breakpoints.

Disable GDB’s auto-debuginfo download (Ubuntu)

Recent Ubuntu versions of GDB try to download debug symbols over the network, causing extremely slow startup:

1

echo "set debuginfod enabled off" >> ~/.gdbinit

Safety breakpoints

Every time you launch gdb bomb, immediately set two breakpoints:

1
2

(gdb) b explode_bomb    # Intercepts the bomb whenever it's about to explode
(gdb) b phase_1         # Breakpoint for the current phase (swap for phase_2, phase_3, etc.)

Input stream ownership: the #1 rookie trap

This is the most important concept throughout the entire lab — always know who you’re talking to:

Terminal shows You’re talking to What you can type
(gdb) prompt GDB debugger Debug commands: c, r, disassemble, x/s, etc.
Blinking cursor only The bomb program Defusal passwords! Never type GDB commands here

If the program hangs or is waiting for input, press Ctrl + C to forcibly interrupt it and get the (gdb) prompt back.

Phase 1: String Comparison

Key concepts: x86-64 calling conventions + reading memory strings

Phase 1 is a warm-up. You just need to find a string hidden in memory.

Disassembling phase_1 reveals dead-simple logic: compare your input against a preset string in memory. If they match, you pass.

(gdb) disassemble phase_1

0x0000000000400ee0 <+0>:  	sub    $0x8,%rsp
0x0000000000400ee4 <+4>: 	mov    $0x402400,%esi               # Key! Address 0x402400 → 2nd argument
0x0000000000400ee9 <+9>:  	call   0x401338 <strings_not_equal> # Call string comparison
0x0000000000400eee <+14>: 	test   %eax,%eax                    # Return 0 = strings equal
0x0000000000400ef0 <+16>: 	je     0x400ef7 <phase_1+23>        # Return 0 → pass
0x0000000000400ef2 <+18>: 	call   0x40143a <explode_bomb>      # Non-zero → explode
0x0000000000400ef7 <+23>: 	add    $0x8,%rsp
0x0000000000400efb <+27>: 	ret

Flow analysis:

  1. mov $0x402400, %esi: By the x86-64 calling convention, %rsi/%esi is the second argument. strings_not_equal’s signature is strings_not_equal(char *input, char *target), so 0x402400 is the target string’s memory address.
  2. call strings_not_equal: Returns 0 in %eax if the strings match.
  3. test %eax, %eax + je: Check if the return value is 0; if so, jump past the explosion.

Key takeaway: x86-64 calling convention — %rdi (1st arg), %rsi (2nd arg), %rdx (3rd arg), %rcx (4th arg). Return value always goes in %rax/%eax.

GDB cracks it instantly:

1

(gdb) x/s 0x402400

The screen prints Border relations with Canada have never been better. — that’s the Phase 1 password.

C equivalent:

    if (strings_not_equal(input, "Border relations with Canada have never been better.") != 0) {

Array offset calculation:

In assembly you don’t see num[i], only offset(%rsp). With %rsp as the base address and int = 4 bytes:

Element Index Offset Assembly notation
num[0] 0 0×4=0 (%rsp)
num[1] 1 1×4=4 0x4(%rsp)
num[2] 2 2×4=8 0x8(%rsp)
num[3] 3 3×4=12 0xc(%rsp)
num[4] 4 4×4=16 0x10(%rsp)
num[5] 5 5×4=20 0x14(%rsp)
num[6] 6 6×4=24 0x18(%rsp) (sentinel, no data stored)

Core formula: address = base_address + (index × element_size)

Key concept: ja vs jg

Instruction Full name Comparison mode Use case
ja Jump if Above Unsigned All bits treated as positive; negative numbers become huge
jg Jump if Greater Signed MSB is sign bit; supports negative comparisons

Using ja means if you input a negative number like -1, its two’s complement 0xFFFFFFFF is 4294967295 in unsigned — far greater than 7 — triggering an instant explosion.

Jump table addressing formula: target_address = table_base(0x402470) + (index × 8)

0x0000000000400fd2 <+4>:  	mov    %edx,%eax                   # %eax = high
0x0000000000400fd4 <+6>:  	sub    %esi,%eax                   # %eax = high - low
0x0000000000400fd6 <+8>:  	mov    %eax,%ecx
0x0000000000400fd8 <+10>: 	shr    $0x1f,%ecx                  # Extract sign bit (positive→0, negative→1)
0x0000000000400fdb <+13>: 	add    %ecx,%eax                   # Fix for negative division
0x0000000000400fdd <+15>: 	sar    $1,%eax                     # %eax = (high-low)/2
0x0000000000400fdf <+17>: 	lea    (%rax,%rsi,1),%ecx          # %ecx = low + mid = the actual mid

# Compare val with mid
0x0000000000400fe2 <+20>: 	cmp    %edi,%ecx                   # mid vs val
0x0000000000400fe4 <+22>: 	jle    0x400ff2 <func4+36>         # mid ≤ val → go right/hit

# Branch A: mid > val → search left half
0x0000000000400fe6 <+24>: 	lea    -0x1(%rcx),%edx             # high = mid - 1
0x0000000000400fe9 <+27>: 	call   0x400fce <func4>             # Recurse
0x0000000000400fee <+32>: 	add    %eax,%eax                   # result = 2 × result

# Branch B: mid == val → direct hit!
0x0000000000400ff2 <+36>: 	mov    $0x0,%eax                   # Return 0 directly
0x0000000000400ff9 <+43>: 	jge    0x401007 <func4+57>

# Branch C: mid < val → search right half
0x0000000000400ffb <+45>: 	lea    0x1(%rcx),%esi              # low = mid + 1
0x0000000000400ffe <+48>: 	call   0x400fce <func4>             # Recurse
0x0000000000401003 <+53>: 	lea    0x1(%rax,%rax,1),%eax       # result = 2 × result + 1

Key optimization: shr $0x1f, %ecx for sign-bit extraction

The assembly uses sar (arithmetic shift right) for division, but sar rounds down for negative numbers, while C integer division requires rounding toward zero:

Expression C requires sar alone gives
15 / 2 7 7 ✓
-15 / 2 -7 -8 ✗

The compiler’s trick: first shr $0x1f to extract the sign bit (0 for positive, 1 for negative), then add it to the dividend, then sar. This corrects the negative division bias.

Deriving num1:

How to make func4 return 0?

  • Left path: result = 2 × sub-result. If sub-result is 0, stays 0 — but needs multiple recursion rounds.
  • Right path: result = 2 × sub-result + 1. The LSB is always 1, so you can never compose a 0.
  • Direct hit on mid: result is immediately 0, no recursion needed.

Initial low=0, high=14: mid = 0 + (14-0)/2 = 7. Enter 7, and func4 hits on the first comparison, returning 0 immediately.

Note: values that can produce 0 via pure left-path recursion are 0, 1, 3, and 7 — but 7 is the most intuitive.

int func4(int val, int low, int high) {
    int mid = low + (high - low) / 2;
    if (mid > val) {
        return 2 * func4(val, low, mid - 1);       // Left half
    } else if (mid < val) {
        return 2 * func4(val, mid + 1, high) + 1;  // Right half
    } else {
        return 0;                                   // Direct hit!
    }
}

void phase_4(char *input) {
    int num1, num2;
    if (sscanf(input, "%d %d", &num1, &num2) != 2) { explode_bomb(); }
    if (num1 > 14) { explode_bomb(); }
    if (func4(num1, 0, 14) != 0) { explode_bomb(); }
    if (num2 != 0) { explode_bomb(); }
}

Answer: 7 0

Core Formulas

  • Array offset: address = base + (index × element_size)
  • Jump table addressing: target_address = table_base + (index × 8) (64-bit pointers are 8 bytes)
  • sscanf argument mapping: 3rd arg %rdx → first %d; 4th arg %rcx → second %d
  • ja vs jg: ja = unsigned comparison (Above); jg = signed comparison (Greater)

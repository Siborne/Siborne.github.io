Codex APP Complete Guide: From Installation to Automation

A comprehensive walkthrough of Codex APP: sandbox permissions, parallel projects, GPT Image generation, plan mode, Git Worktree, cloud execution, Skills/MCP, scheduled automation, and Computer Use.

Key Takeaways

  • Codex APP is the most powerful Codex product form — generous free quota, full-featured, no rate limits or bans
  • Sandbox: OS-level security isolation; out-of-the-box files and network are blocked by default; three permission tiers
  • Multi-project parallelism: Run multiple projects and conversations simultaneously, physically isolated
  • Plan Mode: Align first, execute later — prevents costly rework from AI misunderstanding
  • Git Worktree: Branch-level parallel development in separate folders, true isolation
  • Skills/MCP: Reusable professional capability packs + standardized external tool integration
  • Scheduled automation: Plugins + cron tasks + MEMORY experience accumulation

Why Codex APP?

Codex comes in four product forms, and Codex APP is currently the strongest. Compared to Claude Code:

  • Higher quota, usable even with free accounts
  • More features: built-in browser, image generation, plugin marketplace, scheduled tasks
  • No rate limits, bans, or downgrades
  • Faster onboarding: install and go

This article dissects every feature of Codex APP across 12 sections.

1. Installation & Setup

Prerequisites

Install these three before Codex APP:

  • Git
  • Node.js
  • VS Code

Installation Steps

  1. Go to the Codex website and download the installer (Windows / Mac)
  2. Follow the installer prompts
  3. Launch and sign in with your ChatGPT account (free accounts work)
  4. On first launch, select the type of work you want Codex to handle — it will pre-install matching plugins and Skills
  5. Choose your primary use case: programming / daily work
  6. Click to initialize the sandbox

Mac vs Windows: Features are nearly identical. The only difference is that Computer Use (automatic computer operation) is currently Mac-only.

2. Basic Usage

Three-Column Layout

Codex APP uses a classic three-column layout:

  • Left: Task list (projects + conversations)
  • Center: Chat window
  • Right: Multi-function area (browser, terminal, file tree, etc.)

Project Management

Register local folders as Codex projects via “Add Project → Use Existing Folder”. Each project manages conversations independently with zero interference.

Parallel Tasks

Codex supports multi-project, multi-conversation parallel execution. Task list icons indicate status:

  • 🔵 Blue dot → Completed
  • 🟢 Green label → Awaiting approval
  • 🔄 Spinner → Running

Conversation Management

  • New conversation: Ctrl + N (Win) / Cmd + N (Mac)
  • Search history: Ctrl + G / Cmd + G (searches titles only, not content)
  • Archive/Restore: Click archive to hide conversations; restore from “Settings → Archived Conversations”
  • Auto-generated titles: Each conversation title is AI-summarized; double-click to rename

Permission System: The Sandbox

Codex’s permission system revolves entirely around the Sandbox — a textbook Harness Engineering implementation that constrains AI capabilities at the OS level.

Default restrictions:

Restriction Description
In-sandbox files Direct read/write by default, no per-file approval needed
Out-of-sandbox files Blocked
Network access Blocked by default

These hard limits are enforced by OS-level mechanisms (Seatbelt/Sandbox on Mac, equivalent on Windows), not by model compliance.

Three permission tiers:

Tier Description Recommendation
Manual approval Every privilege escalation requires manual confirmation Safest but tedious
Auto-review Small model auto-reviews low-risk operations; high-risk prompts manual approval ✅ Recommended
Full access Bypass all sandbox restrictions ⚠️ Use with caution

When Codex needs to access out-of-sandbox files or the network, it will request an Escalation.

Context Management

  • The circle in the top-right corner shows current context usage
  • When limits are exceeded, Codex auto-compresses conversation history
  • You can also type /compact to manually trigger compression
  • Rule of thumb: Clearing > Compressing. Start a fresh conversation after completing a task to keep AI focused.

Model Selection

  • Choose thinking intensity based on task complexity
  • Generally use the latest model (e.g., ChatGPT 5.5)
  • Fast mode: 50% faster, but consumes 2× quota

Quota View

Check “Settings → Remaining Quota” for two limits:

  • 5-hour limit
  • Weekly limit

Usage pauses when either limit is reached and automatically resumes at the reset time.

3. Image Generation

Codex has built-in GPT Image (currently the most powerful AI image model), allowing image generation directly within conversations.

Typical uses:

  • Web page illustrations, carousel images
  • Stylized maps from annotated screenshots
  • Maintaining visual consistency across multiple images

Steer Function

When AI execution veers off course, don’t let it continue. Click the Steer button in the conversation (or press Ctrl + Enter) to take the wheel mid-execution and correct the AI’s direction.

In settings, you can choose whether new instructions “queue” or “steer directly”. The recommended default is queuing + manually clicking steer when needed.

4. Plan Mode

For all complex tasks, enable Plan Mode first to align granularity with the AI.

Workflow:

  1. Click the plus icon in the chat window → Enable “Plan Mode”
  2. Enter your requirements; Codex will first communicate details via question cards
  3. Codex outputs a complete work plan
  4. Review and confirm, then click “Execute Plan”
  5. Codex executes and automatically opens the built-in browser on the right for verification

Plan Mode’s value: Avoids massive rework from AI misinterpretation. Especially suited for architecture migrations and large feature development.

Built-in Browser + Annotations

  • The right multi-function area includes a built-in browser for project preview
  • Click the “Annotate” button, select page elements, and add comments — the AI will modify accordingly
  • Changes are visible in real time

5. Code Management

Codex APP is not a traditional IDE and doesn’t offer full code editing. It’s recommended to pair it with VS Code.

Git Initialization

Let Codex initialize your project as a Git repository:

  • Auto-creates .gitignore, excluding unnecessary files
  • Git-related buttons appear in the top-right corner after initialization

VS Code Integration

Click the VS Code button in the top-right to open the project in one click, or specify a default IDE in settings.

GitHub Sync

Let Codex create a repository on GitHub and push your code. All Git/GitHub operations can be done through conversation.

Advanced Tip 1: Conversation Fork + Git Rollback

When you regret a change and want to pretend it never happened:

  1. Conversation Fork: Find the pre-change point in the conversation, click the fork button → fork locally to get a conversation copy without the changes
  2. Code Rollback: Copy the target commit hash from VS Code’s Source Control, and ask Codex to revert the code to that state

Forking only rolls back conversation history. Code needs separate Git rollback. Together they achieve full conversation + code rollback.

Advanced Tip 2: Git Worktree

Worktree essentially creates a new branch via Git and copies the branch code to a separate folder, enabling multi-branch parallel development.

Use cases:

  1. Right-click project → Create permanent worktree (e.g., customer-rating, store-info)
  2. Develop different features in different worktrees in parallel, with zero interference
  3. After completion, merge each back to main
  4. Remove temporary worktrees

Worktree’s core value: different branches live in different folders — true physically isolated parallel development.

6. Cloud Execution

When you don’t have your computer handy, or want tasks to run in the background cloud:

Prerequisite: Code must be synced to GitHub.

Workflow:

  1. Push local code to GitHub
  2. Select “Link Codex Web” as the run mode
  3. Click “Go to Cloud”, enter the repository name and requirements
  4. Codex initializes cloud environment → downloads code → AI analyzes → completes modifications
  5. Click “Create Pull Request” → code is submitted to GitHub as a PR
  6. After review, Merge on GitHub
  7. Back on local, Sync Changes to pull the latest code

Best scenario: Out and about, approving via phone while Codex completes tasks in the cloud.

7. Memory System

Every new conversation starts with zero project memory. Complex projects need a memory system to avoid repeating context.

Method 1: Project-level AGENTS.md

Create an AGENTS.md file in the project root; it’s automatically injected as context for every conversation.

You can write it by hand or let Codex generate it after reading the project:

1

Have Codex read the entire current folder and save the project knowledge into AGENTS.md

Method 2: Global AGENTS.md

Edit under “Settings → Personalization → Custom Instructions”. Applies to all projects.

File location: C:\Users\<username>\.codex\AGENTS.md

Practical example — preventing accidental file deletion:

1
2

Never use scripts to batch-delete files or directories. Only use Remove-Item to delete one at a time.
If batch deletion is absolutely required, stop and let the user handle it manually.

Experimental Feature: Enable Memory

The “Enable Memory” setting can auto-extract memories from chats and carry them into new conversations. Still experimental.

8. Plugins & Automation

Plugin Marketplace

Left sidebar → Plugins, divided into two categories:

Type Description
Plugins Third-party service capability injection (GitHub, Gmail, Netlify, etc.)
Skills Professional capability guides with directory structure

Example: GitHub + Gmail Workflow

  1. Install GitHub plugin and Gmail plugin
  2. Authorize login
  3. Enter: /github show me my top 10 starred repos + /gmail email me a summary

Scheduled Automation

Turn the above workflow into a scheduled task:

1

Turn the above into an automation — email me every Friday at 4 PM

After creation, in the “Automation” panel you can:

  • Edit execution frequency (weekly/daily/hourly)
  • Switch models (use mini models for simple tasks)
  • Click “Run Now” to test

Execution experience is written to MEMORY.md, making subsequent runs more stable.

More Automation Ideas

With browser automation or Computer Use:

  • Summarize daily Teams chat messages into a work report
  • Auto-check-in on websites on schedule
  • Periodically scrape data and generate reports

9. Skills

Skills are professional capability packs for AI Agents — essentially manuals with directory structure. Encapsulate workflows, expertise, and standards into Skills to make Agent task execution more stable and efficient.

Three Installation Methods

1. Official Skills

Install directly from the plugin marketplace. Example: Remotion — lets AI create animated videos programmatically.

1

/remotion Generate a 3D conical pendulum animation with force analysis, angular velocity slowly increasing over time

2. Third-party Skills

Download from GitHub and place in your project:

1
2
3
4

project-folder/
  └── .codex/
      └── skills/
          └── downloaded-skill-file

Then add the project to Codex and invoke the Skill with a slash command.

3. Custom Skills

Use the built-in Skill Creator to create:

1
2
3
4
5

/skill-creator Create a skill:
When I provide a video and subtitle file —
Step 1: Read subtitles, convert to Markdown notes, auto-add punctuation and paragraph breaks,
       for code demonstrations / UI interactions, add screenshot placeholder markers at sentence end
Step 2: Use ffmpeg to take screenshots at markers, replace placeholders with local images

Long prompt tip: Use Shift + Enter for line breaks, not Enter (which sends the message).

Once created, all similar future tasks become a single slash command.

10. MCP

MCP (Model Context Protocol) is a standardized toolbox for large models, enabling AI to interact with external services.

Entry Point

“Settings → MCP Servers → Add Server”

Example: Supabase MCP

Supabase is an open-source, free PostgreSQL cloud database.

  1. Create a project on Supabase → Connect → MCP Client → Select Codex → Copy URL
  2. Add MCP server in Codex, transport type “Streamable HTTP”, paste the URL
  3. Run codex mcp login supabase in the terminal to authorize
  4. Restart Codex

Now you can operate the database through conversation:

1
2

Use Supabase MCP to create a booking table.
User form data is written from the backend using a connection pool.

11. Computer Use

⚠️ Currently Mac-only

After installing the Computer Use plugin, Codex can directly operate your computer:

  • Open chat apps, find your boss, and send messages
  • Open browser, check GitHub kanban boards, summarize project progress
  • Generate English briefs and send to your boss

Features

  • Uses a virtual mouse running in the background, not occupying the current window
  • Can be composed into scheduled automation tasks (e.g., auto-send brief every day at 5 PM)
  • On Mac, recommend enabling “Prevent system sleep during execution”

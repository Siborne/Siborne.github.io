Comparison of Traditional Processes and Threads in Computing

I. Basic Definitions

  • Process

    • The basic unit of resource allocation and scheduling in an operating system.
    • A single dynamic execution instance of a program.
    • Possesses an independent virtual memory space (including code segment, data segment, heap, stack), file descriptors, signal handlers, and other resources.
    • Processes are isolated from each other: a crash in one process generally does not directly affect other processes (they can collaborate via IPC).

  • Thread

    • An execution flow within a process, and the basic unit of CPU scheduling.
    • All threads within the same process share that process’s memory space and system resources (such as global variables, open files, etc.).
    • Each thread independently owns its own stack, registers, program counter, and other private data for saving execution state.
    • Also known as a Light-Weight Process (LWP); correspondingly, a traditional process is called a Heavy-Weight Process (HWP).

II. Scheduling Mechanisms

Item Process Thread
Scheduling Unit The OS treats a process as the resource allocation unit The OS treats a thread as the CPU scheduling unit
Context Switch Requires a full switch: virtual memory, registers, file descriptors, etc. → high overhead Only switches thread-private data (stack, registers, PC) → low overhead
Scheduling Mode Kernel scheduling, round-robin time slicing, preemptive execution Also scheduled by the kernel (or partially in user mode)

III. Concurrency and Communication

  • Process Concurrency

    • Collaboration via Inter-Process Communication (IPC) (such as pipes, message queues, shared memory, etc.).
    • High context switch overhead → lower concurrency efficiency.

  • Thread Concurrency

    • Can communicate directly via shared memory (since they share the same address space).
    • Lightweight context switching → high concurrency efficiency.

IV. Resource Ownership

Resource Type Process Thread
Virtual Memory Space Independent Shared with the owning process
File Descriptors/Handles Independent Shared
Signal Handlers Independent Shared (but thread-specific behavior can be configured)
Stack, Registers, PC (Each process has at least one main thread) Each thread independently owns

V. System Overhead Comparison

Operation Process Thread
Creation/Destruction Requires allocating/reclaiming MB-level memory and initializing numerous resources → high overhead (involves system calls) Only requires allocating KB-level stack space and a small amount of metadata → low overhead (can be done in user mode)
Context Switch Cost High (full context switch) Low (only switches private registers and stack)

VI. Summary

A process is the basic unit for resource allocation and scheduling in the OS, representing a single dynamic execution instance of a program. Each process has an independent virtual memory space (code segment, data segment, heap, stack), file descriptors, signal handlers, and other resources. Processes are isolated from each other; a crash in one process does not directly affect other processes (they collaborate via Inter-Process Communication, or IPC). The creation and destruction of a process are managed by the OS kernel and incur significant overhead.

A thread is an execution flow within a process and is the basic unit of CPU scheduling. All threads within the same process share that process’s memory space and system resources (such as global variables), and each thread independently owns private data such as its own stack, registers, and program counter for saving its execution state. The creation and destruction of threads are managed by the process, and the system overhead is far smaller than that of processes.

Because threads share many characteristics of traditional processes, they are also known as light-weight processes (LWP) or process elements; correspondingly, traditional processes are called heavy-weight processes (HWP), which are essentially tasks with only a single thread.

In terms of scheduling, both processes and threads are scheduled by the OS kernel through round-robin time-slicing preemptive execution. The difference between them lies in the fact that the OS treats a process as the unit of resource allocation, and switching a process requires a full context switch (virtual memory, registers, file descriptors, etc.), whereas a thread is the basic unit of CPU scheduling, and switching a thread only requires switching the thread’s private data (stack, registers, program counter).

From a concurrency perspective, both are used for multi-tasking and concurrent execution to improve resource utilization. The difference is that concurrency between processes requires Inter-Process Communication (IPC), incurs high context switch overhead, and has lower concurrency efficiency, whereas threads can share the same process’s memory space, communicate directly via shared memory, have lightweight context switches, and achieve high concurrency efficiency.

From the perspective of resource ownership, a process owns an independent virtual memory space, file handles, signal handlers, and other resources; threads share the owning process’s virtual memory and system resources, independently owning only thread-private data such as the stack and registers.

In terms of system overhead, the creation and destruction of a process both require allocating and reclaiming memory and initializing resources (MB-level), incurring high system overhead (involving system calls); whereas the creation and destruction of a thread only requires allocating stack space and a small amount of metadata (KB-level), incurring low system overhead (which can be implemented in user mode).

OpenCode Advanced Tips: Parallel Scheduling and Workflow Mastery

Master OpenCode's killer features: Session parallel processing, Ultra Work multi-agent collaboration, Timeline rollback, and Ralph Loop — doubling your AI coding efficiency.

Key Highlights

  • Session Parallel: OpenCode’s killer feature — run multiple tasks simultaneously without interference, doubling efficiency.
  • Ultra Work Mode: Type ULW and the main agent automatically breaks down tasks and dispatches multiple sub-agents to work in parallel.
  • @-mention Agents: Assign the frontend specialist to frontend work and the architect to code reviews — the right person for the right job.
  • Timeline Time Machine: Roll back to any historical checkpoint at any time, making bold experimentation cost-free.
  • Ralph Loop: Let the AI work in a continuous loop for hours to tackle extremely difficult tasks.

1. Session Parallel: Let AI Do Multiple Things at Once

This is OpenCode’s biggest differentiating advantage over other AI programming tools. Traditional tools are serial — you must finish one task before starting the next. OpenCode can run multiple Sessions simultaneously without interference.

Basic Operations

# Currently running Task A, want to start Task B at the same time
/new                          # Create a new Session

# Enter Task B's requirements in the new Session
# Both Sessions run in the background simultaneously

# Check the status of all Sessions
/sessions                     # Spinning symbol = currently running

# Switch to a specific Session
/session <id>

# Go back to the previous Session
/session prev

Real-World Scenario

Suppose you’re building a “Draw and Guess” mini-game with two independent requirements:

Requirement A: Add a timer — start counting on first stroke, game over if exceeding 20 seconds Requirement B: Allow the brush color to be adjustable

Traditional approach: Finish A first, then start B → Requirement B sits idle for 5–10 minutes.

OpenCode approach:

1
2
3
4

1. Enter Requirement A, AI starts working
2. Type /new to create a new Session
3. Enter Requirement B, AI starts working
4. Type /sessions to check progress — both are running ↓

1
2

Session 1  ◐  Adding timer logic...
Session 2  ◐  Adding color picker...

Both requirements are developed entirely in parallel, compressing total time from 15 minutes to 8 minutes.

Important Notes

  • Sessions are fully isolated from each other; modifying the same file may cause conflicts, so assign them to different modules
  • Background Sessions won’t automatically notify you when done — you need to manually check with /sessions
  • You can always /new a third, fourth session… there’s no limit

When to Use It?

Scenario Suitable Notes
Creating a complete project from scratch ✅ Excellent Auto-splits frontend, backend, and docs
Multi-module parallel development ✅ Excellent Clear division of work among agents
Small single-file edits ❌ Not recommended Using a sledgehammer to crack a nut — slower
Simple bug fixes ❌ Not recommended A normal conversation is faster

💡 Tip: The higher the complexity, the greater Ultra Work’s value. For simple tasks, the scheduling overhead actually makes it slower.

Real Results

A pet store website was created using Ultra Work mode:

  • Todo List automatically generated
  • 3 background tasks started simultaneously
  • Emoji used as decoration in the absence of any image assets
  • Clean interface, smooth interactions, and complete animations

4. Timeline Time Machine: Experiment Fearlessly, Roll Back Anytime

What’s the scariest thing in programming? Changing a ton of code only to realize you went in the wrong direction — and now you can’t go back. Timeline is your undo button.

Basic Usage 

1

/timeline

This lists every conversation step in the current Session. Select any checkpoint:

  • Revert: Both code and chat content roll back to that checkpoint — as if nothing happened
  • View: See what changes the AI made at that point

Real-World Scenario 

1
2
3

1. You asked the AI to refactor a module → the result is unsatisfactory
2. /timeline → select the checkpoint before the refactor → Revert
3. Code returns to pre-refactor state, try a different approach

Pro Tips

  • After completing a milestone, mentally note that checkpoint (which conversation number)
  • Boldly try radical approaches — you can always one-click roll back
  • Compare two solutions: Revert to Solution A → review → Revert to Solution B → compare

🕐 This is the programming equivalent of “save/load game”, allowing you to fearlessly explore any possibility.

5. Ralph Loop: Make the AI Push Through to the End 

1

/ralph-loop

This mode makes the AI continuously loop until the task is truly complete. Perfect for tough nuts that require repeated iteration.

Use Cases 

1
2
3

"Refactor the entire project using the latest Spring Boot 4 standards until all test cases pass"
"Check every file under src/ for coding standard violations and fix each one"
"Add comprehensive unit tests to the project until coverage reaches 90%"

Compared to Ultra Work

Ultra Work Ralph Loop
Mechanism Parallel decomposition, multi-agent Serial loop, continuous iteration
Best for Building from scratch, multi-module Refactoring, fixing, compliance tasks
Duration Minutes to tens of minutes Potentially hours
Endpoint Task decomposition complete Termination condition met

⚠️ Ralph Loop may run for a very long time — keep an eye on your API credit consumption.

6. Daily Efficiency Tips

1. Use /compact to Save Context

When you’ve been chatting with the AI for many rounds and the context window is nearly full:

1

/compact

The AI condenses previous conversations into a summary, freeing up space to continue working. No need to start a new conversation and lose context.

2. Use /init to Help AI Quickly Get Up to Speed on a New Project

When entering a new project, let the AI read through the code first:

1

/init

The AI scans the entire project and generates agents.md as a system prompt. All subsequent conversations will be based on this understanding, greatly improving efficiency.

3. Share Your Coding Process 

1
2
3

/share      # Generate a shareable link showing the full conversation and code changes
/unshare    # Revoke sharing — the link becomes invalid
/export     # Export the conversation log as a file

Use cases:

  • Show colleagues how you used AI to solve a problem
  • Document pitfalls encountered for team reference
  • Source material for blog posts

4. View Available Models 

1

/models

Models with the free tag are free to use. GLM-4.7 and MiniMax-2.1 have decent coding ability suitable for lightweight tasks.

5. Quick Code Paste (VS Code Extension)

In VS Code, select a code snippet → Ctrl + Alt + K → directly paste it into the OpenCode chat window.

Eliminates the context-switching cost of copy-paste and keeps you in flow.

8. A Real-World Case

After installing Oh My OpenAgent, I wanted to adjust the agent model configuration — make GitHub Copilot the primary and the free OpenCode Zen the fallback.

I directly said in the OpenCode conversation:

“其实我还有你免费的OpenCode Zen，但是我已经登录 GitHub Copilot 了，你帮我修改一下”

The AI set OpenCode Zen as the primary on the first try — because I didn’t specify the priority. After correcting it:

“不是，是 GitHub Copilot 作为主力，OpenCode Zen 自带的免费模型作为备选”

The AI immediately corrected it and updated oh-my-openagent.json, setting all agents to use github-copilot/* as primary and opencode/* as fallback.

💡 Lesson: When describing requirements to the AI, always clearly state the priority hierarchy.

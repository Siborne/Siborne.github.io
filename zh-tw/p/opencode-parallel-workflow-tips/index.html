OpenCode 新手進階：並行排程與使用技巧全攻略

掌握 OpenCode 的殺手級功能：Session 並行、Ultra Work 多智慧體、Timeline 回退、Ralph Loop 迴圈，讓 AI 程式設計效率翻倍。

AI Computer Tools
简体中文 English 日本語

核心要點概括

  • Session 並行：OpenCode 殺手級功能，多個任務同時跑，互不干擾，效率翻倍。
  • Ultra Work 模式：輸入 ULW，主智慧體自動拆解任務、排程多個子智慧體並行幹活。
  • @ 指定智慧體：讓擅長前端的幹前端，擅長架構的做評審，人盡其才。
  • Timeline 時光機：隨時回退到任意歷史節點，大膽試錯零成本。
  • Ralph Loop：讓 AI 迴圈工作數小時，攻堅極難任務。

一、Session 並行：讓 AI 同時幹多件事

這是 OpenCode 相比其他 AI 程式設計工具最大的差異化優勢。傳統工具只能序列——一個任務跑完才能開始下一個。OpenCode 可以同時開啟多個 Session，互不干擾。

實戰場景

假設你在開發一個「你畫我猜」小遊戲，有兩個獨立需求：

需求 A：增加一個計時器，首次落筆開始計時，超過 20 秒遊戲失敗 需求 B：畫筆可以調節顏色

傳統做法：先做完 A，再做 B → 需求 B 白白等待 5-10 分鐘。

OpenCode 做法：

1
2
3
4

1. 輸入需求 A，AI 開始工作
2. 輸入 /new，建立新 Session
3. 輸入需求 B，AI 開始工作
4. 輸入 /sessions 檢視進度，兩個都在跑 ↓

1
2

Session 1  ◐  正在新增計時器邏輯...
Session 2  ◐  正在新增顏色選擇器...

兩個需求完全並行開發，總耗時從 15 分鐘壓縮到 8 分鐘。

注意事項

  • Session 之間完全隔離，修改同一檔案可能衝突，建議分配給不同模組
  • 後臺 Session 不會自動通知完成，需要手動 /sessions 檢視
  • 可以隨時 /new 開第三個、第四個……沒有數量限制

二、Ultra Work：一鍵召喚 AI 程式設計團隊

什麼時候用？

場景 適用 說明
從零建立完整專案 ✅ 極佳 自動拆分前端、後端、文件
多模組並行開發 ✅ 極佳 各智慧體分工明確
單檔案小修改 ❌ 不推薦 殺雞用牛刀，反而更慢
簡單 bug 修復 ❌ 不推薦 普通對話更快

💡 經驗：複雜度越高，Ultra Work 的價值越大。簡單任務反而會因為排程開銷變慢。

實際效果

用 Ultra Work 模式建立了一個寵物商店網站：

  • 自動拆分 Todo List
  • 同時開啟 3 個後臺任務並行執行
  • 在沒有任何圖片素材的情況下，用 emoji 作為裝飾
  • 介面清新、互動流暢、動畫完整

安裝了 Oh My OpenAgent（OMO）後，你擁有一個 AI 程式設計團隊。透過 @ 可以點名讓特定智慧體幹活。

四、Timeline 時光機：隨意試錯，隨時回退

程式設計中最怕什麼？改了一大堆程式碼，發現方向錯了，又回不去。Timeline 就是你的後悔藥。

基本用法 

1

/timeline

會列出當前 Session 的每一步對話記錄，選擇任意節點：

  • Revert：程式碼和聊天內容同時回退到該節點，就像什麼都沒發生過
  • View：檢視當時 AI 做了什麼修改

實戰場景 

1
2
3

1. 你讓 AI 重構了某個模組 → 效果不理想
2. /timeline → 選擇重構前的節點 → Revert
3. 程式碼回到重構前，換個思路重新來

技巧

  • 完成一個階段性任務後，在心裡記下那個節點（第幾次對話）
  • 大膽嘗試激進方案——反正可以一鍵回退
  • 對比兩個方案：Revert 到 A 方案 → 看看效果 → Revert 到 B 方案 → 對比

🕐 這就是程式設計版的「存檔/讀檔」，讓你敢於探索任何可能性。

五、Ralph Loop：讓 AI 死磕到底 

1

/ralph-loop

這個模式會讓 AI 持續迴圈工作，直到任務真正完成。適合那些需要反覆迭代的硬骨頭。

適用場景 

1
2
3

"使用 Spring Boot 4 最新標準重構整個專案，直到所有測試用例透過"
"逐個檢查 src/ 下所有檔案的程式碼規範，修復每一個違規項"
"為專案新增完整的單元測試，直到覆蓋率達到 90%"

和 Ultra Work 的區別

Ultra Work Ralph Loop
工作機制 並行拆分、多智慧體協作 序列迴圈、持續迭代
適合 從零構建、多模組專案 重構、修復、達標類任務
耗時 幾分鐘到十幾分鍾 可能數小時
終點 任務拆解完成 滿足終止條件

⚠️ Ralph Loop 可能執行很久，注意 API 額度消耗。

六、日常提速小技巧

1. 善用 /compact 節省上下文

當你和 AI 聊了很多輪，上下文視窗快滿時：

1

/compact

AI 會把之前的對話提煉成一個摘要，釋放空間繼續工作。不需要開新對話丟失上下文。

2. 用 /init 讓 AI 快速上手新專案

進入一個新專案時，先讓 AI 通讀程式碼：

1

/init

AI 會掃描整個專案，生成 agents.md 作為系統提示詞。之後任何對話都會基於這個理解，效率大幅提升。

3. Share 分享你的程式設計過程 

1
2
3

/share      # 生成分享連結，展示完整對話和程式碼修改
/unshare    # 取消分享，連結失效
/export     # 匯出對話記錄為檔案

適合場景：

  • 給同事展示你是如何用 AI 解決某個問題的
  • 記錄踩坑過程，供團隊參考
  • 寫部落格時的素材

4. 檢視可用模型 

1

/models

帶 free 標記的是免費模型。GLM-4.7 和 MiniMax-2.1 程式設計能力不錯，適合輕量任務。

5. 快捷貼上程式碼（VS Code 外掛）

在 VS Code 中選中程式碼片段 → Ctrl + Alt + K → 直接貼上到 OpenCode 對話方塊。

省去複製貼上的切換成本，保持心流。

八、一個真實案例

在 Oh My OpenAgent 安裝完成後，想調整 Agent 模型配置——讓 GitHub Copilot 作為主力，免費的 OpenCode Zen 作為備選。

直接在 OpenCode 對話中說：

“其實我還有你免費的OpenCode Zen，但是我已經登入 GitHub Copilot 了，你幫我修改一下”

AI 第一次把 OpenCode Zen 設成了主力——因為沒說清楚主次關係。糾正後：

“不是，是 GitHub Copilot 作為主力，OpenCode Zen 自帶的免費模型作為備選”

AI 立即修正，更新了 oh-my-openagent.json，所有 Agent 都用 github-copilot/* 為主、opencode/* 為 fallback。

💡 教訓：跟 AI 描述需求時，主次關係一定要說清楚。

電腦中傳統行程和執行緒的比較

一、基本定義

  • 行程（Process）

    • 是作業系統進行資源分配和排程的基本單位。
    • 是程式的一次動態執行過程。
    • 擁有獨立的虛擬記憶體空間（包括程式碼段、資料段、堆、棧）、檔案描述符、訊號處理器等資源。
    • 行程間相互隔離：一個行程崩潰通常不會直接影響其他行程（可透過 IPC 協作）。

  • 執行緒（Thread）

    • 是行程內的一個執行流，是 CPU 排程的基本單位。
    • 同一行程內的所有執行緒共享該行程的記憶體空間和系統資源（如全域變數、打開的檔案等）。
    • 每個執行緒獨立擁有自己的棧、暫存器、程式計數器等私有資料，用於儲存執行狀態。
    • 又稱輕型行程（Light-Weight Process, LWP）；相應地，傳統行程稱為重型行程（Heavy-Weight Process, HWP）。

二、排程機制

專案 行程 執行緒
排程單位 作業系統以行程為資源分配單位 作業系統以執行緒為CPU排程單位
上下文切換 需完整切換：虛擬記憶體、暫存器、檔案描述符等 → 開銷大 僅切換執行緒私有資料（棧、暫存器、PC） → 開銷小
排程方式 核心排程，時間片輪轉、搶佔式執行 同樣由核心排程（或部分使用者態實現）

三、併發與通訊

  • 行程併發

    • 透過行程間通訊（IPC）協作（如管道、訊息佇列、共享記憶體等）。
    • 上下文切換開銷大 → 併發效率較低。

  • 執行緒併發

    • 可直接透過共享記憶體通訊（因共享同一位址空間）。
    • 上下文切換輕量 → 併發效率高。

四、資源擁有情況

資源型別 行程 執行緒
虛擬記憶體空間 獨立 共享所屬行程的記憶體
檔案描述符/控制代碼 獨立 共享
訊號處理器 獨立 共享（但可設定執行緒特定行為）
棧、暫存器、PC （每個行程至少一個主執行緒有） 每個執行緒獨立擁有

五、系統開銷對比

操作 行程 執行緒
建立/銷燬 需分配/回收 MB 級記憶體，初始化大量資源 → 開銷大（涉及系統呼叫） 僅需分配 KB 級棧空間和少量元資料 → 開銷小（可在使用者態實現）
切換成本 高（完整上下文切換） 低（僅切換私有暫存器和棧）

六、總結

行程（Process）是 OS 中進行資源分配和排程的基本單位，是程式的一次動態執行過程。每個行程都擁有獨立的虛擬記憶體空間（程式碼段、資料段、堆、棧）、檔案描述符、訊號處理器等資源。同時，行程間相互隔離，一個行程崩潰不會直接影響其他行程（透過行程間通訊 IPC 協作）。並且，行程的建立和銷燬由作業系統核心管理，開銷較大。

執行緒（Thread）是屬於行程內的一個執行流，是 CPU 排程的基本單位。同一個行程內的所有執行緒共享此行程的記憶體空間的系統資源（如全域變數），每一個執行緒都獨立擁有棧、暫存器、程式計數器等私有資料，用於儲存執行狀態。並且，執行緒的建立和銷燬都由行程管理，在系統開銷方面遠小於行程。

因為執行緒擁有傳統行程的所具有的很多特徵，因此又稱為輕型行程（light-weight process，LWP）或行程元；相應地把傳統行程稱為重型行程（heavy-weight process，HWP），它相當於只有一個執行緒的任務。

在排程方面，行程和執行緒均由作業系統核心排程，透過時間片輪轉搶佔執行。他們之間的不同之處在於，作業系統以行程為資源分配單位，行程切換需完整上下文切換（虛擬記憶體、暫存器、檔案描述符等），而執行緒則是 CPU 排程的基本單位，切換僅需切換執行緒的私有資料（棧、暫存器、程式計數器）

從併發的角度來說，二者均用於多工併發執行，提升資源利用率。不同的是，行程之間的併發需要透過行程間通訊（IPC），上下文切換開銷大，併發效率較低，而執行緒可以共享同一個行程的記憶體空間，可以透過共享記憶體直接通訊，上下文切換輕量，併發效率高。

在擁有資源的角度上看，行程擁有獨立的虛擬記憶體空間、檔案控制代碼、訊號處理器等資源；執行緒則共享所屬行程的虛擬記憶體和系統資源、僅僅獨立擁有棧、暫存器等執行緒私有資料。

在系統開銷方面，執行緒的建立和銷燬都需要分配和回收記憶體並且初始化資源（MB 級），系統開銷大（涉及了系統呼叫）；而執行緒的建立和銷燬僅需分配棧和少量元資料（KB 級），系統開銷小（可以在使用者態實現）。

核心ポイント

  • Codex APP は現在最も強力な Codex 製品形態で、無料枠が大きく、機能が充実し、アカウント停止やレート制限なし
  • サンドボックス機構：OS レベルのセキュリティ分離、デフォルトでサンドボックス外ファイルとネットワークアクセスを禁止、3段階の権限設定
  • マルチプロジェクト並行：複数プロジェクト・複数会話を同時実行、物理的に隔離されて干渉しない
  • プランモード：まず認識を合わせてから実行、AI の誤解による手戻りを防止
  • Git Worktree：ブランチレベルの並行開発、異なるフォルダで真の隔離を実現
  • Skills/MCP：再利用可能な専門能力パック + 標準化された外部ツール連携
  • スケジュール自動化：プラグイン + 定期タスク + MEMORY 経験蓄積で、使うほど安定

なぜ Codex APP を選ぶのか？

Codex には4つの製品形態がありますが、Codex APP は現在最も強力です。Claude Code と比較して：

  • より大きな利用枠、無料アカウントでも使用可能
  • より豊富な機能、内蔵ブラウザ、画像生成、プラグインマーケットプレイス、定期タスク
  • レート制限、アカウント停止、性能低下なし
  • より速いオンボーディング、インストール後すぐに使用可能

本記事では12のセクションに分けて、Codex APP の全機能を詳しく解説します。

一、インストールと初期設定

準備

Codex APP をインストールする前に、以下の3つをインストールしてください：

  • Git
  • Node.js
  • VS Code

インストール手順

  1. Codex 公式サイト からインストーラーをダウンロード（Windows / Mac 対応）
  2. インストーラーの指示に従って進める
  3. 起動後、ChatGPT アカウントでログイン（無料アカウントで可）
  4. 初回起動時に Codex に処理させたい作業タイプを選択すると、対応するプラグインと Skills が事前インストールされる
  5. 主な使用シーンを選択：プログラミング / 日常業務
  6. サンドボックスを初期化

Mac vs Windows：機能はほぼ同じ。唯一の違いは Computer Use（コンピュータ自動操作）が現在 Mac のみ対応であること。

二、基本操作

3カラムレイアウト

Codex APP はクラシックな3カラムレイアウトを採用：

  • 左側：タスクリスト（プロジェクト + 会話）
  • 中央：チャットウィンドウ
  • 右側：多機能エリア（ブラウザ、ターミナル、ファイルツリーなど）

プロジェクト管理

「プロジェクトを追加 → 既存のフォルダを使用」でローカルフォルダを Codex プロジェクトとして登録。各プロジェクトは独立して会話を管理し、互いに干渉しない。

並行タスク

Codex はマルチプロジェクト・マルチ会話の並行実行をサポート。タスクリストのアイコンで状態を表示：

  • 🔵 青い点 → 完了
  • 🟢 緑のラベル → 承認待ち
  • 🔄 回転アイコン → 実行中

会話管理

  • 新規会話：Ctrl + N（Win）/ Cmd + N（Mac）
  • 履歴検索：Ctrl + G / Cmd + G（タイトルのみ検索、内容は検索しない）
  • アーカイブ/復元：アーカイブボタンで会話を非表示、「設定 → アーカイブ済み会話」から復元可能
  • タイトル自動生成：各会話のタイトルは AI が内容に基づいて自動要約、ダブルクリックで名前変更も可能

権限システム：サンドボックス機構

Codex の権限システムはすべて**サンドボックス（Sandbox）**を中心に構築されています。これは Harness Engineering コンセプトの典型的な実装であり、OS レベルのメカニズムで AI の能力を制御可能な範囲に制約します。

デフォルトの制限：

制限 説明
サンドボックス内ファイル デフォルトで直接読み書き、ファイルごとの承認不要
サンドボックス外ファイル アクセス禁止
ネットワークアクセス デフォルトで禁止

これらのハード制限はモデルの自律性ではなく、OS の低レベルメカニズムによって強制されます（Mac は Seatbelt/Sandbox、Windows は同等のメカニズム）。

3段階の権限レベル：

レベル 説明 推奨
手動承認 すべての権限昇格に手動確認が必要 最も安全だが煩雑
自動審査 小規模モデルが低リスク操作を自動審査、高リスクのみ手動確認 ✅ 推奨
フルアクセス サンドボックス制限をすべて解除 ⚠️ 注意して使用

Codex がサンドボックス外のファイルやネットワークにアクセスする必要がある場合、「エスカレーション（Escalate）」申請を発行します。

コンテキスト管理

  • 右上の円が現在のコンテキスト使用量を表示
  • 制限を超えると Codex が自動圧縮で履歴を圧縮
  • /compact で手動圧縮も可能
  • 経験則：クリア > 圧縮。タスク完了後に新規会話を開始し、AI の集中力を維持する。

モデル選択

  • タスクの複雑さに応じて思考強度を選択
  • 通常は最新モデル（ChatGPT 5.5 など）を使用
  • 高速モード：50% 高速化、ただし2倍の利用枠を消費

利用枠の確認

「設定 → 残りの利用枠」で2つの制限を確認可能：

  • 5時間制限
  • 週間制限

いずれかが上限に達すると使用が一時停止され、リセット時間後に自動復旧します。

三、画像生成

Codex は GPT Image（現在最も強力な AI 画像生成モデル）を内蔵しており、会話内で直接画像を生成できます。

主な用途：

  • Web ページの画像、カルーセル画像の生成
  • スクリーンショットの注釈に基づくスタイライズドマップの生成
  • 複数画像のスタイル一貫性の維持

Steer（ステアリング）機能

AI の実行方向が逸れた場合、そのまま続行させないでください。会話内のステアリングボタンをクリック（または Ctrl + Enter を押下）して、途中でハンドルを握り、AI の実行方向を修正します。

設定で新規指示を「キューイング」か「直接ステアリング」か選択可能。デフォルトはキューイング + 必要時に手動ステアリングを推奨。

四、プランモード

すべての複雑なタスクでは、まずプランモード（Plan Mode）を有効にして、AI との粒度の一致を確保することを推奨します。

ワークフロー：

  1. チャットウィンドウのプラスアイコンをクリック → 「プランモード」を有効化
  2. 要件を入力すると、Codex はまず質問カードで詳細を確認
  3. Codex が完全な作業計画を出力
  4. レビューして確認後、「この計画を実行」をクリック
  5. Codex が実行し、右側の内蔵ブラウザを自動的に開いて検証

プランモードの価値：AI の誤解による大量の手戻りを防ぎ、アーキテクチャ移行や大規模機能開発などのタスクに特に適しています。

内蔵ブラウザ + 注釈

  • 右側の多機能エリアで内蔵ブラウザを開きプロジェクトをプレビュー可能
  • 「注釈」ボタンをクリックし、ページ要素を選択してコメントを追加すると、AI がそれに基づいて修正
  • 修正プロセスはリアルタイムで確認可能

五、コード管理

Codex APP は従来の IDE ではなく、完全なコード編集機能を提供しません。VS Code との併用を推奨します。

Git 初期化

Codex にプロジェクトを Git リポジトリとして初期化させる：

  • .gitignore を自動作成し、不要なファイルを除外
  • 初期化完了後、右上に Git 関連ボタンが表示される

VS Code 連携

右上の VS Code ボタンをクリックしてプロジェクトをワンクリックで開くか、設定でデフォルト IDE を指定可能。

GitHub 同期

Codex に GitHub でリポジトリを作成しコードをプッシュさせることができ、すべての Git/GitHub 操作は会話で完結します。

上級テクニック1：会話フォーク + Git ロールバック

変更を後悔し「なかったこと」にしたい場合：

  1. 会話フォーク（Fork）：会話内で変更前の位置を見つけ、フォークボタンをクリック → ローカルに派生し、変更を含まない会話コピーを取得
  2. コードロールバック：VS Code の Source Control で対象のコミットハッシュをコピーし、Codex にコードをその状態に戻させる

フォークは会話履歴のみをロールバックします。コードは別途 Git でロールバックが必要です。両者を組み合わせることで会話 + コードの完全なロールバックを実現します。

上級テクニック2：Git Worktree

Worktree は Git で新しいブランチを作成し、ブランチのコードを独立したフォルダにコピーすることで、マルチブランチ並行開発を実現します。

使用シーン：

  1. プロジェクトを右クリック → 永続ワークツリーを作成（例：customer-rating、store-info）
  2. 異なるワークツリーで異なる機能を並行開発、互いに干渉しない
  3. 開発完了後、それぞれをメインにマージ
  4. 一時ワークツリーを削除

Worktree の核心的価値：異なるブランチが異なるフォルダに配置され、真の物理的隔離による並行開発を実現。

六、クラウド実行

手元に PC がない場合や、タスクをバックグラウンドのクラウドで実行したい場合：

前提条件：コードが GitHub に同期されていること。

操作フロー：

  1. ローカルコードを GitHub にプッシュ
  2. 実行モードで「Codex Web に連携」を選択
  3. 「Cloud に移動」をクリックし、リポジトリ名と要件を入力
  4. Codex がクラウド環境を初期化 → コードをダウンロード → AI が分析 → 修正を完了
  5. 「プルリクエストを作成」をクリック → コードが PR として GitHub に提出
  6. レビュー後、GitHub 上で Merge
  7. ローカルに戻り Sync Changes で最新コードを同期

最適なシーン：外出先でスマートフォンから承認し、Codex にクラウドでタスクを完了させる。

七、メモリシステム

新しい会話のたびに、AI のプロジェクトに対する記憶は空白です。複雑なプロジェクトでは、繰り返しの説明を避けるためにメモリシステムが必要です。

方法1：プロジェクトレベルの AGENTS.md

プロジェクトのルートディレクトリに AGENTS.md ファイルを作成すると、毎回の会話で自動的にコンテキストとして注入されます。

手書きも可能ですが、Codex にプロジェクトを読み込ませて自動生成させることもできます：

方法2：グローバル AGENTS.md

「設定 → パーソナライズ → カスタム指示」で編集し、すべてのプロジェクトに適用されます。

ファイルの場所：C:\Users\<ユーザー名>\.codex\AGENTS.md

設定の「メモリを有効化」は、チャットから自動的にメモリを抽出し新しい会話に持ち越すことができます。現在も実験的機能です。

例：GitHub + Gmail 連携

  2. 認証ログイン
  3. 入力：/github スター数トップ10のオープンソースプロジェクトを表示 + /gmail 自分にサマリーをメール送信

  • 定期的にデータを取得してレポートを生成

十、MCP

MCP（Model Context Protocol）は大規模モデルの標準化されたツールボックスであり、AI が外部サービスと対話できるようにします。

エントリーポイント

「設定 → MCP サーバー → サーバーを追加」

例：Supabase MCP

Supabase はオープンソースで無料の PostgreSQL クラウドデータベースです。

  1. Supabase でプロジェクトを作成 → Connect → MCP クライアント → Codex を選択 → URL をコピー
  2. Codex で MCP サーバーを追加、転送タイプは「ストリーミング HTTP」を選択、URL を貼り付け
  3. ターミナルで codex mcp login supabase を実行して認証
  4. Codex を再起動

その後、会話でデータベースを操作できます：

1
2

ユーザーのフォームデータはバックエンドから connection pool 方式で書き込む

十一、コンピュータ自動化（Computer Use）

⚠️ 現在 Mac のみ対応

Computer Use プラグインをインストールすると、Codex が直接あなたのコンピュータを操作できます：

  • チャットアプリを開いて上司にメッセージを送信
  • ブラウザを開いて GitHub かんばんボードを確認し、プロジェクトの進捗をまとめる
  • 英語のブリーフを生成して上司に送信

特徴

  • 仮想マウスでバックグラウンド実行、現在のウィンドウを占有しない
  • スケジュール自動化タスクとして編成可能（例：毎日午後5時に自動でブリーフを送信）
  • Mac では「実行中のシステムスリープを防止」を有効にすることを推奨

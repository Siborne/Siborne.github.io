OpenCode のキラー機能をマスター：Session 並行、Ultra Work マルチエージェント、Timeline ロールバック、Ralph Loop ループで AI プログラミング効率を倍増。

核心ポイント概要

  • Session 並行：OpenCode のキラー機能。複数タスクを同時実行し、互いに干渉せず、効率倍増。
  • Ultra Work モード：ULW と入力するだけで、メインエージェントが自動でタスクを分解し、複数のサブエージェントを並行稼働。
  • @ でエージェント指定：フロントエンドが得意なエージェントにフロントエンドを、アーキテクチャが得意なエージェントにレビューを任せ、適材適所。
  • Timeline タイムマシン：任意の履歴ポイントにいつでもロールバック可能。大胆に試行錯誤してゼロコスト。
  • Ralph Loop：AI に数時間ループ作業させ、超難関タスクに挑む。

一、Session 並行：AI に同時に複数の作業をさせる

これは OpenCode が他の AI プログラミングツールと比較して最大の差別化優位性です。従来のツールは逐次処理のみ——1つのタスクが完了しないと次に進めません。OpenCode は複数の Session を同時に開き、互いに干渉しません。

実践シナリオ

「お絵かき当て」ミニゲームを開発していると仮定し、2つの独立した要件があります：

要件 A：タイマーを追加。最初の描画でタイマー開始、20秒超過でゲーム失敗 要件 B：描画色を調整可能にする

従来の方法：A を先に完了させ、その後 B → 要件 B は 5〜10 分無駄に待機。

OpenCode の方法：

1
2
3
4

1. 要件 A を入力、AI が作業開始
2. /new と入力し、新規 Session を作成
3. 要件 B を入力、AI が作業開始
4. /sessions で進捗確認、両方とも実行中 ↓

1
2

Session 1  ◐  タイマーロジックを追加中...
Session 2  ◐  カラーピッカーを追加中...

2つの要件を完全に並行開発、合計所要時間を15分から8分に短縮。

注意事項

  • Session 間は完全に隔離されており、同一ファイルの変更は競合の可能性あり。異なるモジュールへの割り当てを推奨。
  • バックグラウンド Session は完了を自動通知しないため、手動で /sessions 確認が必要。
  • いつでも /new で3つ目、4つ目……を起動可能。数に制限なし。

二、Ultra Work：ワンクリックで AI プログラミングチームを召喚

いつ使うべき？

シナリオ 適性 説明
ゼロからプロジェクト作成 ✅ 最適 フロント・バック・ドキュメントを自動分割
マルチモジュール並行開発 ✅ 最適 各エージェントの役割が明確
単一ファイルの小修正 ❌ 非推奨 鶏を割くに牛刀を用いる、むしろ遅くなる
簡単なバグ修正 ❌ 非推奨 通常の会話の方が速い

💡 経験則：複雑さが高いほど Ultra Work の価値は大きい。簡単なタスクはスケジューリングのオーバーヘッドでむしろ遅くなる。

実際の効果

Ultra Work モードでペットショップサイトを作成：

  • 自動で Todo List を分解
  • 3つのバックグラウンドタスクを同時に並行実行
  • 画像素材が一切ない状態で、emoji を装飾として使用
  • インターフェースは爽やか、インタラクションはスムーズ、アニメーションは完全

四、Timeline タイムマシン：自由に試行錯誤、いつでもロールバック

プログラミングで一番怖いのは？大量のコードを変更した後、方向性が間違いだったと気づき、元に戻せないこと。Timeline はあなたの後悔を帳消しにする薬です。

基本的な使い方 

1

/timeline

現在の Session の各ステップの会話記録を表示し、任意のノードを選択：

  • Revert：コードとチャット内容をそのノードまで同時にロールバック。何もなかったかのように。
  • View：その時 AI がどのような変更を行ったかを確認。

実践シナリオ 

1
2
3

1. AI にあるモジュールのリファクタリングを依頼 → 結果が理想的でない
2. /timeline → リファクタリング前のノードを選択 → Revert
3. コードがリファクタリング前に戻り、別のアプローチで再挑戦

コツ

  • 段階的なタスクが完了したら、そのノード（何回目の会話か）を心に留めておく
  • 大胆にラジカルな案を試す——どうせワンクリックで戻せる
  • 2つの案を比較：案 A に Revert → 効果を確認 → 案 B に Revert → 比較

🕐 これはプログラミング版の「セーブ/ロード」。あらゆる可能性を探求する勇気を与えてくれます。

五、Ralph Loop：AI に最後までやり抜かせる 

1

/ralph-loop

このモードは AI を継続的にループ作業させ、タスクが本当に完了するまで続けます。繰り返しのイテレーションが必要な難題に適しています。

適用シナリオ 

1
2
3

"Spring Boot 4 の最新標準でプロジェクト全体をリファクタリングし、すべてのテストケースがパスするまで"
"src/ 以下のすべてのファイルのコード規約を1つずつチェックし、違反項目をすべて修正"
"カバレッジが90%に達するまで、プロジェクトに完全なユニットテストを追加"

Ultra Work との違い

Ultra Work Ralph Loop
動作メカニズム 並行分割、マルチエージェント連携 逐次ループ、継続的イテレーション
適性 ゼロからの構築、マルチモジュール リファクタリング、修正、目標達成型
所要時間 数分〜十数分 数時間の可能性
終了点 タスク分割の完了 終了条件の満足

⚠️ Ralph Loop は長時間実行される可能性があるため、API 利用枠の消費に注意。

六、日常の効率化テクニック

1. /compact を活用してコンテキストを節約

AI と何度も会話してコンテキストウィンドウがほぼ満杯になったとき：

1

/compact

AI は過去の会話を要約に凝縮し、スペースを解放して作業を継続します。新しい会話を始めてコンテキストを失う必要はありません。

2. /init で AI を新規プロジェクトに素早く適応させる

新しいプロジェクトに入ったら、まず AI にコードを一通り読ませます：

1

/init

AI がプロジェクト全体をスキャンし、システムプロンプトとして agents.md を生成します。以降のすべての会話はこの理解に基づき、効率が大幅に向上します。

3. Share でプログラミングの過程を共有 

1
2
3

/share      # 共有リンクを生成。完全な会話とコード変更を表示
/unshare    # 共有を解除。リンクが無効に
/export     # 会話記録をファイルにエクスポート

適したシーン：

  • AI を使ってどのように問題を解決したかを同僚に見せる
  • トラブルシューティングの過程を記録し、チームの参考に
  • ブログ執筆の素材として

4. 利用可能なモデルを確認 

1

/models

free マーク付きは無料モデル。GLM-4.7 と MiniMax-2.1 はプログラミング能力が高く、軽量タスクに適しています。

5. クイックコード貼り付け（VS Code プラグイン）

VS Code でコードスニペットを選択 → Ctrl + Alt + K → OpenCode のダイアログに直接貼り付け。

コピー＆ペーストの切り替えコストを省き、フロー状態を維持。

一言まとめ

小さな作業は直接会話、大きな作業は ULW、並行は Session、間違えたら Timeline でロールバック、粘り強くやるなら Ralph Loop。

八、実例

Oh My OpenAgent のインストール完了後、Agent モデル設定を調整——GitHub Copilot をメインに、無料の OpenCode Zen をバックアップにしたい場合。

OpenCode の会話で直接こう言います：

“実はあなたの無料のOpenCode Zenもあるけど、もうGitHub Copilotにログインしてるから、修正してくれる？”

AI は最初、OpenCode Zen をメインに設定しました——主従関係が明確でなかったためです。修正後：

“違う、GitHub Copilotをメインにして、OpenCode Zen付属の無料モデルをバックアップにして”

AI は即座に修正し、oh-my-openagent.json を更新。すべての Agent が github-copilot/* をメイン、opencode/* をフォールバックとして設定されました。

💡 教訓：AI に要件を伝えるときは、主従関係を必ず明確に伝えること。

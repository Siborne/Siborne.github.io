はじめに

自分だけのブログを持ちたいけれど、サーバー管理やホスティング費用に悩まされたくない——そんな方に最適なのが Hugo です。現在最も人気のある静的サイトジェネレーターの一つである Hugo と、無料ホスティングの GitHub Pages を組み合わせれば、30分もかからずに機能的で美しい個人ブログを公開できます。

本ガイドでは、環境構築からテーマの徹底カスタマイズ、自動デプロイまでを一挙に解説します。Hugo が初めての方も、既存ブログのアップグレードを検討している方も、すぐに使える知見が満載です。

1. 基本環境のセットアップ

まずは二つのコアツール、Git と Hugo を準備します。

1.1 Git のインストール

Git 公式サイトから各プラットフォーム向けのインストーラーをダウンロードし、デフォルト設定でインストールします。

インストール完了後、ターミナルで以下のコマンドを実行して確認します：

1

git --version

バージョン番号が表示されればインストール成功です。

1.2 Hugo のインストール

Hugo の GitHub Releases ページにアクセスし、最新バージョンをダウンロードします。

  • Windows ユーザー：hugo_extended と windows_amd64 を含む zip ファイルを選択
  • macOS ユーザー：brew install hugo
  • Linux ユーザー：パッケージマネージャーまたはバイナリを直接ダウンロード

Hugo のバイナリを使いやすいディレクトリに配置し、パスを控えておきます。これから頻繁に使用します。

なぜ extended バージョンが必要なのか？ Stack テーマは Hugo の組み込み SCSS コンパイル機能に依存しています。extended バージョンのみが完全な SCSS/SASS 処理をサポートしており、通常版ではテーマのスタイルが正しく生成されません。

2. 初めての Hugo サイト作成

2.1 プロジェクトの初期化

Hugo バイナリのあるディレクトリでターミナルを開き、以下のコマンドを実行します：

1

hugo new site my-blog

これで標準的な Hugo プロジェクトの骨格が生成されます。my-blog はお好みの名前に変更可能です。

プロジェクトディレクトリに移動します：

1

cd my-blog

2.2 ローカルプレビュー

Hugo 内蔵の開発サーバーを起動します：

1

hugo server -D

-D フラグは下書き（draft）記事も表示するため、ローカル開発時に便利です。

http://localhost:1313 にアクセスすると空白のページが表示されますが、これは正常です。まだテーマをインストールしていないためです。Ctrl + C でサーバーを停止しましょう。

3. Stack テーマの設定

Hugo のエコシステムには数百の無料テーマがあります。本ガイドでは、美しいカード型レイアウト、ダークモード、シンタックスハイライト、多言語対応を備えた Stack テーマを中心に解説します。

3.1 テーマのダウンロード

themes.gohugo.io でテーマを閲覧できます。Stack については、Releases ページから直接最新バージョンをダウンロードします。

アーカイブを展開し、テーマフォルダごとプロジェクトの /themes ディレクトリに配置します。

Git サブモジュールの使用も推奨されます：git submodule add https://github.com/CaiJimmy/hugo-theme-stack.git themes/hugo-theme-stack

3.2 設定の適用

Stack テーマにはサンプルサイトが同梱されており、exampleSite ディレクトリにあります。その中の content フォルダと hugo.yaml をプロジェクトルートにコピーし、元の hugo.toml（存在する場合）と content/post/rich-content サンプルファイルを削除します。

hugo.yaml を開き、theme フィールドが /themes 内のテーマフォルダ名と一致していることを確認します：

1

theme: hugo-theme-stack

再度開発サーバーを起動します：

1

hugo server -D

ブラウザを更新すると、クリーンでエレガントな Stack ブログが表示されます。hugo.yaml にはサイトタイトル、説明、ソーシャルリンク、ナビゲーションメニューなど多くの調整可能なパラメータがあります。時間をかけて確認し、必要に応じて変更してください。

4. GitHub Pages へのデプロイ

4.1 手動デプロイ

まず GitHub で {あなたのユーザー名}.github.io という名前のリポジトリを作成します。

リポジトリの Settings -> Pages に移動し、Source を Deploy from a branch、Branch を main に設定して保存します。GitHub が自動的に https://{ユーザー名}.github.io という URL を有効にします。

ローカルに戻り、プロジェクトルートで以下のコマンドを実行します：

1

hugo -D

ルートディレクトリに public フォルダが生成されます。これが完全な静的サイトです。public に移動して GitHub にプッシュします：

1

cd public
git init
git add .
git commit -m "first commit"
git branch -M main
git remote add origin https://github.com/{ユーザー名}/{ユーザー名}.github.io.git
git push -u origin main

初回プッシュ時に認証を求められる場合があります（パスワードの代わりに GitHub CLI または Personal Access Token の使用を推奨）。アップロードが完了したら、https://{ユーザー名}.github.io にアクセスしてブログを確認できます。

4.2 自動デプロイ（GitHub Actions）

記事を書くたびに手動でビルドとプッシュを行うのは面倒です。GitHub Actions を使えば、このワークフロー全体を自動化できます。

準備

  1. Hugo ソースファイル用に別のリポジトリを作成します（例：my-blog-source）
  2. GitHub の Settings -> Developer settings -> Personal access tokens -> Tokens (classic) でトークンを生成
  3. トークンの有効期限を 無期限 に設定し、repo と workflow スコープを付与
  4. 生成されたトークンをソースリポジトリの Settings -> Secrets and variables -> Actions に PERSONAL_TOKEN として保存

ワークフローの作成

Hugo プロジェクトのルートに .github/workflows/deploy.yaml を作成します：

5. コメントシステムの統合

Hugo は静的ページを生成するため、コメント機能は組み込まれていません。しかし GitHub の Issue または Discussion の仕組みを活用することで、無料でコメント機能を追加できます。

5.1 utterances（Issue ベース）

utterances は各記事のコメントを、指定したリポジトリの Issue として保存します。

  • utterances app を対象リポジトリにインストール
  • hugo.yaml に設定：
1
2
3
4

comments:
  provider: utterances
  utterances:
    repo: "{あなたのGitHubユーザー名}/{リポジトリ名}"

5.2 giscus（Discussion ベース）

giscus は utterances と同様の仕組みですが、データを Issues ではなく Discussions に保存し、よりモダンな UI を提供します。返信のネストやリアクションにも対応しています。

  • giscus app をリポジトリにインストールし、リポジトリの Settings で Discussions 機能を有効化
  • giscus 公式サイト にアクセスし、手順に沿って設定するとパラメータが生成されます
  • hugo.yaml に設定：
 1

 3

comments:
  provider: giscus
  giscus:
    repo: "{あなたのGitHubユーザー名}/{リポジトリ名}"
    repoID: "{giscus 生成の repoID}"
    category: "{Discussion カテゴリ名}"
    categoryID: "{giscus 生成の categoryID}"
    mapping: "pathname"
    reactionsEnabled: "1"
    emitMetadata: "0"
    inputPosition: "bottom"
    lang: "ja"

このブログでも giscus を使用しており、非常に良い体験が得られています。Stack テーマは両方のソリューションをネイティブサポートしており、hugo.yaml に入力するだけで利用できます。

6. ビジュアルカスタマイズ

6.1 カスタム背景画像

高解像度の画像を assets/background に配置します。

layouts/partials/footer/custom.html に以下を追加します（ファイルがなければ作成）：

<style>
  body {
    background: url({{ (resources.Get "background/背景画像ファイル名.png").Permalink }}) no-repeat center top;
    background-size: cover;
    background-attachment: fixed;
  }
</style>

background-attachment: fixed により、スクロールしても背景が固定され、パララックス風の奥行き効果が生まれます。

6.2 動的背景エフェクト

桜吹雪エフェクト

パーティクルネットワーク（particles.js）

particles.js は星空、接続線、バブルなど多彩なエフェクトを生成できる強力なパーティクルアニメーションライブラリです。

  1. particles.js GitHub から particles.min.js をダウンロードし、assets/background に配置
  2. 公式オンライン設定ツール でパラメータを調整し、設定ファイルを particlesjs-config.json として assets/background に保存
  3. 設定ファイル内の detect_on は window に変更する必要があります

7. 機能拡張

7.1 最終更新日の表示

hugo.yaml で Git ベースの日付追跡を有効にします：

1
2
3
4
5
6

enableGitInfo: true

frontmatter:
  lastmod:
    - :git
    - :fileModTime

Hugo は各ファイルの Git コミット日時を最終更新日として優先的に使用し、Git 情報がない場合はファイルの変更日時にフォールバックします。

layouts/partials/article/components/details.html を編集し、<footer class="article-time"> 内に以下を挿入します：

1
2
3
4
5
6
7
8

{{- if ne .Lastmod .Date -}}
    <div class="article-lastmod">
        {{ partial "helper/icon" "clock" }}
        <time>
            {{ .Lastmod.Format ( or .Site.Params.dateFormat.lastUpdated "Jan 02, 2006 15:04 MST" ) }}
        </time>
    </div>
{{- end -}}

重要：enableGitInfo を有効にした場合、GitHub Actions の checkout ステップで fetch-depth: 0 を設定し、完全なコミット履歴を取得する必要があります。

<script>
  function initTocHide() {
    let toc = document.querySelector(".widget--toc");
    if (!toc) return;

    window.addEventListener('scroll', function() {
      let openUl = document.querySelectorAll(".open");
      if (openUl.length > 0) {
        openUl.forEach((ul) => ul.classList.remove("open"))
      }
      let currentLi = document.querySelector(".active-class");
      if (!currentLi) return;

      if (currentLi.children.length > 1) {
        currentLi.children[1].classList.add("open")
      }
      let ul = currentLi.parentElement;
      do {
        ul.classList.add("open");
        ul = ul.parentElement.parentElement
      } while (ul !== undefined && (ul.localName === 'ul' || ul.localName === 'ol'))
    });
  }
  initTocHide();
</script>

未読のセクションは自動的に折りたたまれ、現在のセクションのみが展開されるため、長文記事の目次ナビゲーションが大幅に向上します。

    let rightSideBar = document.querySelector(".right-sidebar");
    if (!rightSideBar) return;

    let btn = document.createElement("div");

    btn.onclick = () => window.scrollTo({ top: 0, behavior: "smooth" });
    rightSideBar.appendChild(btn);

    window.onscroll = function() {
      if (document.body.scrollTop > 20 || document.documentElement.scrollTop > 20) {
        btn.style.display = "block";
      } else {
        btn.style.display = "none";
      }
    };
  }

</script>

<script>
  function initCodeCollapse() {
    document.querySelectorAll('.highlight').forEach(function(block) {
      let pre = block.querySelector('pre');
      if (!pre || pre.scrollHeight <= 420) return;

      let btn = document.createElement('div');
      btn.className = 'code-expand-btn';
      btn.textContent = 'コードを展開';
      block.appendChild(btn);

      btn.addEventListener('click', function() {
        let expanded = pre.classList.toggle('expanded');
        btn.textContent = expanded ? 'コードを折りたたむ' : 'コードを展開';
      });
    });
  }
  initCodeCollapse();
</script>

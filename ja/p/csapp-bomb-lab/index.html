简体中文 English 繁體中文

アセンブリは辛い——でも乗り越えた先に新しい世界が広がっている。

Bomb Lab は CMU 15-213（CS:APP）コースで最も象徴的な実験の一つです。bomb というバイナリ実行ファイルが与えられ、6つのフェーズで構成されています。各フェーズでは特定のパスワードを入力する必要があり、間違えると爆弾が爆発します（プログラムが「BOOM!」と表示して減点）。手元にあるのは実行ファイルと GDB デバッガだけ。目標は逆アセンブルして各フェーズのパスワードを推論することです。

本記事では、6つのフェーズ全ての解体プロセスを、アセンブリコードの1行ずつの解説から GDB の実践テクニック、そしてアセンブリロジックを C 言語に翻訳するところまで完全攻略します。

事前準備

解体を始める前に、GDB 環境の設定と安全用ブレークポイントを設定します。

GDB の自動デバッグ情報ダウンロードを無効化（Ubuntu ユーザー必須）

最新の Ubuntu の GDB はデフォルトでデバッグシンボルをネットワーク経由でダウンロードするため、起動が極端に遅くなります：

1

echo "set debuginfod enabled off" >> ~/.gdbinit

安全用ブレークポイント

gdb bomb を起動するたびに、まず2つのブレークポイントを設定します：

1
2

(gdb) b explode_bomb    # 爆弾が爆発しようとするたびに GDB が即座に停止
(gdb) b phase_1         # 現在のフェーズにブレークポイントを設定（以降 phase_2, phase_3 等に切替）

入力ストリームの所有権：初心者が最もハマる罠

これは実験全体を通して最も重要な概念です——今誰と対話しているのかを常に意識すること：

端末の表示 対話相手 入力できるもの
(gdb) プロンプトあり GDB デバッガ デバッグコマンド：c、r、disassemble、x/s 等
緑色の点滅カーソルのみ 爆弾プログラム 解体パスワード！絶対にここで GDB コマンドを入力しない

プログラムがフリーズしたり爆弾が入力を待っている状態であれば、いつでも Ctrl + C でプログラムを強制中断し、(gdb) プロンプトを取り戻せます。

Phase 1：文字列比較

ポイント：x86-64 関数呼び出し規約 + メモリ文字列の読み取り

第1フェーズは最も簡単なウォームアップです。メモリ上に隠されたターゲット文字列を見つけるだけです。

phase_1 を逆アセンブルすると、極めてシンプルなロジックが明らかになります：入力文字列とメモリ上のプリセット文字列を比較し、一致すればクリアです。

0x0000000000400ee0 <+0>:  	sub    $0x8,%rsp

0x0000000000400eee <+14>: 	test   %eax,%eax                    # 戻り値：0 = 一致
0x0000000000400ef0 <+16>: 	je     0x400ef7 <phase_1+23>        # 戻り値 0 → クリア
0x0000000000400ef2 <+18>: 	call   0x40143a <explode_bomb>      # 非ゼロ → 爆発
0x0000000000400ef7 <+23>: 	add    $0x8,%rsp
0x0000000000400efb <+27>: 	ret

フロー解説：

  1. mov $0x402400, %esi：x86-64 の関数呼び出し規約では、%rsi/%esi が第2引数です。strings_not_equal のシグネチャは strings_not_equal(char *input, char *target) なので、0x402400 がターゲット文字列のメモリアドレスです。
  2. call strings_not_equal：比較関数を呼出し、文字列が一致すれば 0 を %eax に返します。
  3. test %eax, %eax + je：戻り値が 0 ならジャンプしてクリア、そうでなければ爆発。

重要ポイント：x86-64 関数呼び出し規約 —— %rdi（第1引数）、%rsi（第2引数）、%rdx（第3引数）、%rcx（第4引数）。戻り値は常に %rax/%eax に格納。

GDB で一瞬で解決：

1

(gdb) x/s 0x402400

画面に Border relations with Canada have never been better. が表示されます。これが第1フェーズのパスワードです。

    if (strings_not_equal(input, "Border relations with Canada have never been better.") != 0) {

配列オフセット計算：

アセンブリでは num[i] は見えず、オフセット(%rsp) のみです。%rsp をベースアドレス、int は4バイト：

要素 インデックス オフセット アセンブリ表記
num[0] 0 0×4=0 (%rsp)
num[1] 1 1×4=4 0x4(%rsp)
num[2] 2 2×4=8 0x8(%rsp)
num[3] 3 3×4=12 0xc(%rsp)
num[4] 4 4×4=16 0x10(%rsp)
num[5] 5 5×4=20 0x14(%rsp)
num[6] 6 6×4=24 0x18(%rsp)（番兵、データなし）

核心公式：アドレス = ベースアドレス + (インデックス × 要素バイト数)

重要概念：ja vs jg

命令 正式名 比較方式 使用場面
ja Jump if Above 符号なし比較 全ビットを正数扱い、負数は巨大な正数になる
jg Jump if Greater 符号付き比較 最上位ビットを符号ビット扱い、負数比較可能

ここでは ja が使われているため、負数（例：-1）を入力すると、その2の補数 0xFFFFFFFF が符号なしでは 4294967295 となり、7よりはるかに大きいため即座に爆発します。

ジャンプテーブルアドレッシング公式：ジャンプ先アドレス = テーブルベース(0x402470) + (インデックス × 8)

重要な最適化：shr $0x1f, %ecx による符号ビット抽出

アセンブリでは sar（算術右シフト）で除算を行いますが、sar は負数に対して切り下げを行います。一方 C 言語の整数除算はゼロ方向への切り捨てが要求されます：

式 C 言語の要求 sar 単体の結果
15 / 2 7 7 ✓
-15 / 2 -7 -8 ✗

コンパイラの巧妙なテクニック：まず shr $0x1f で符号ビットを抽出し（正→0、負→1）、それを add で被除数に加算してから sar を実行。これで負数除算のズレを補正しています。

num1 の導出：

どうすれば func4 が 0 を返すか？

  • 左半分経路：戻り値 = 2 × 部分結果。部分結果が 0 なら 0 のままですが、複数回の再帰が必要。
  • 右半分経路：戻り値 = 2 × 部分結果 + 1。最下位ビットが常に 1 になり、0 を作ることは不可能。
  • mid に直接命中：戻り値が直接 0 になり、再帰不要。

初期値 low=0, high=14：mid = 0 + (14-0)/2 = 7。7 を入力すれば、func4 は最初の比較で命中し、直接 0 を返します。

注：純粋な左経路の再帰でも 0 を生成できる値は 0, 1, 3, 7 ですが、7 が最も直感的です。

int func4(int val, int low, int high) {
    int mid = low + (high - low) / 2;
    if (mid > val) {
        return 2 * func4(val, low, mid - 1);       // 左半分
    } else if (mid < val) {
        return 2 * func4(val, mid + 1, high) + 1;  // 右半分
    } else {
        return 0;                                   // 命中！
    }
}

void phase_4(char *input) {
    int num1, num2;
    if (sscanf(input, "%d %d", &num1, &num2) != 2) { explode_bomb(); }
    if (num1 > 14) { explode_bomb(); }
    if (func4(num1, 0, 14) != 0) { explode_bomb(); }
    if (num2 != 0) { explode_bomb(); }
}

解答：7 0

Phase 6：リンクリストの再構成と降順ソート

ポイント：二重ループによる重複排除 + 7-x 変換 + リンクリスト走査とポインタ付け替え + 降順検証

これは Bomb Lab 全体の最終ボスで、配列、二重ループ、ポインタ、構造体、リンクリスト操作がすべて詰まっています。1〜6の重複しない数字を6つ入力します。プログラムは各数字を 7-x 変換した後、その順序でプリセットのリンクリストを再リンクし、最終的にリストのノード値が降順であることを検証します。

コマンド 目的

核心公式

  • 配列オフセット：アドレス = ベース + (インデックス × 要素バイト数)
  • ジャンプテーブルアドレッシング：ジャンプ先アドレス = テーブルベース + (インデックス × 8)（64ビットではポインタは8バイト）
  • sscanf 引数対応：第3引数 %rdx → 最初の %d；第4引数 %rcx → 2番目の %d
  • ja vs jg：ja = 符号なし比較（Above）；jg = 符号付き比較（Greater）
